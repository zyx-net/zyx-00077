# 排班考勤异常对账分析工具 - 样例数据

## 目录结构

```
sample-data/
├── normal/                    # 正常数据
│   ├── schedule.csv          # 正常排班表
│   ├── punch.csv             # 正常打卡记录（含各种异常）
│   └── leave.csv             # 调休配置
├── error-missing-employee-id/ # 失败路径1：缺员工编号列
│   └── schedule.csv          # 缺少员工编号列的排班表
├── error-timezone/            # 失败路径2：错误时区配置
│   └── punch.csv             # UTC时区的打卡记录
├── error-config/              # 配置文件
│   ├── timezone-config.json  # 错误的时区配置（UTC）
│   └── correct-config.json   # 正确的时区配置（Asia/Shanghai）
├── cross-day-shift/           # 失败路径3：夜班跨日班次
│   ├── schedule.csv          # 跨日夜班排班表（22:00-06:00）
│   └── punch.csv             # 跨日打卡记录
└── duplicate-punch/           # 失败路径4：同窗口重复打卡
    └── punch.csv             # 5分钟内多次打卡记录
```

## 异常说明

### 正常数据中的异常
- **迟到**：E002(01-15 迟到15分钟), E003(01-16 迟到30分钟), E001(01-17 迟到5分钟)
- **早退**：E002(01-15 早退15分钟, 调休抵扣), E005(01-16 早退5分钟), E001(01-17 早退10分钟)
- **缺卡**：E004(01-15 缺下班卡)
- **加班**：E002(01-16 加班30分钟)

### 失败路径场景

#### 1. 缺员工编号列
- 导入 `error-missing-employee-id/schedule.csv` 时，系统应检测到缺少必填字段「员工编号」
- 错误提示：「缺少必填字段：员工编号」

#### 2. 错误时区配置
- 使用 `error-config/timezone-config.json`（UTC时区）导入 `error-timezone/punch.csv`
- 打卡时间会被错误计算（UTC时间比北京时间晚8小时）
- 切换到 `error-config/correct-config.json`（Asia/Shanghai）后恢复正常

#### 3. 夜班跨日打卡
- 导入 `cross-day-shift/` 下的排班表和打卡记录
- 班次为 22:00-06:00（次日）
- 系统应自动识别跨日班次并正确计算工时
- 异常：E002(01-15 迟到15分钟, 早退10分钟)

#### 4. 同窗口重复打卡
- 导入 `duplicate-punch/punch.csv`
- 包含5分钟内多次打卡的记录
- 系统应自动去重，保留最早的上班打卡和最晚的下班打卡
- E001：上班打卡3次（8:55:00, 8:55:15, 8:55:30）→ 保留8:55:00
- E002：上班2次、下班2次 → 保留最早上班、最晚下班
- E003：下班打卡4次（18:05:00-18:05:15）→ 保留18:05:15

## 验收流程

### 主流程
1. 创建新批次「2024年1月考勤核对」
2. 导入 `normal/schedule.csv`, `normal/punch.csv`, `normal/leave.csv`
3. 系统自动识别异常
4. 人工修正：将E004的缺下班卡标记为「补卡-外出办公」
5. 导出HTML报告和Markdown报告

### 持久化验证
1. 完成主流程后刷新页面
2. 验证批次、原始数据、修正记录仍然存在
3. 进入规则配置页，回滚「迟到检测」规则到v1版本
4. 重新导出报告，验证异常汇总中迟到数量变化
